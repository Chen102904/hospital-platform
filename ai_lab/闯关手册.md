## 0. 开始之前

**先确认你在哪个终端里。** 两者语法不一样，粘错就报 `无法将"PY=..."项识别为 cmdlet`。

### PowerShell（Windows 默认，蓝色窗口）

```powershell
cd "E:\新建文件夹\work项目\2026-10-08-11-50-41\ai_lab"
$PY = "C:\Users\dell\.workbuddy\binaries\python\envs\default\Scripts\python.exe"
& $PY drill.py --check
```

### Git Bash（黑色窗口）

```bash
cd "E:/新建文件夹/work项目/2026-10-08-11-50-41/ai_lab"
PY="C:/Users/dell/.workbuddy/binaries/python/envs/default/Scripts/python.exe"
$PY drill.py --check
```

### 两者的四个差别（记住这张表就不会粘错）

| | PowerShell | Git Bash |
|---|---|---|
| 定义变量 | `$PY = "..."` ← **必须有 `$`** | `PY="..."` ← **不能有 `$`** |
| 用变量 | `& $PY xxx` ← **必须有 `&`** | `$PY xxx` ← **不能有 `&`** |
| 路径斜杠 | `E:\...`（用 `/` 也行） | `E:/...`（用 `\` 会被当转义） |
| 引号 | 双引号 | 双引号或单引号 |

> 最容易错的就是第一行：**少了 `$`，PowerShell 会把整串 `PY=C:/...` 当成一条命令去找**，
> 于是报「无法将该项识别为 cmdlet、函数、脚本文件或可运行程序的名称」。看到这句，就是漏了 `$`。

> **懒人做法**：不定义变量，直接把完整路径写进命令，一条都不出错：
> ```powershell
> & "C:\Users\dell\.workbuddy\binaries\python\envs\default\Scripts\python.exe" drill.py 1
> ```

> **如果看到绿方块变成 `?`**：那是 `✅ ❌ ⚠` 这些符号在 GBK 里不存在。
> 脚本里有兜底 —— **不会崩、汉字全对，只有符号退化成 `?`**。
> 屏幕上看时通常显示正常（控制台走的是另一条通路），只有把输出存成文件或接管道才会看到 `?`。
> 不影响任何判断，别为这个折腾。

> **为什么必须用这个 python**：你机器上 `versions\3.13.12` 那个**没装 flask/requests**。
> 用错的那个，第一关就报 `ModuleNotFoundError: No module named 'requests'`，
> 然后你会以为是自己代码写错了，其实是解释器选错了。

该看到：

```
✅ 解释器  Python 3.13.x
✅ 依赖    requests / flask / pymysql 已装
✅ 密钥    qwen3.7-plus @ maas.qianwenaiapi.com
✅ 数据库  his_ro@localhost/hospital_db 连上了，15 张表
✅ 文档    3 份齐，共 75,346 字节
✅ 缓存    2 个向量缓存
```

有一条 ❌ 就先修，别硬跑。全是 ✅ 或 ⚠️ 就可以开始。

> 端口报"已被占用"是 ⚠️ 不是 ❌。说明上次的服务没关，等跑到第 9、10 关再处理。

## 后面每一关的命令

手册里统一写成 `& $PY drill.py N`（PowerShell 版）。

**两个终端只差一个 `&`：**

| | 写法 | 不加会怎样 |
|---|---|---|
| PowerShell | `& $PY drill.py 1` | 报「表达式或语句中包含意外的标记"drill.py"」 |
| Git Bash | `$PY drill.py 1` | 多了 `&` 会把它丢到后台执行（什么都不显示） |

> PowerShell 里 `$PY` 是**变量**不是命令，必须用调用运算符 `&` 把它当命令执行。
> 你刚才踩的那个 `PY=...` 报错，和这个是同一类问题：**PowerShell 把 `$` 看得很重**。

> 换窗口就要重新定义一次 `$PY` —— 变量不跨窗口。

## 1. 把话说明白 —— `01_hello.py`

```bash
& $PY drill.py 1
```

|            |                                                                                             |
| ---------- | ------------------------------------------------------------------------------------------- |
| **在证明什么**  | URL、方法、Header、Body 四样都对，服务器才认你                                                              |
| **该看到**    | `── 发出去的请求体 ──` 一段 JSON，然后 `── 模型回答 ──`，最后 `耗时：x.x 秒` 和 `token 用量：prompt=17 completion=3xx` |
| **正常但像报错** | `completion` 比 `prompt` 大好几倍。这不是 bug —— 这是推理型模型，**它"想"的过程也计费**                              |
| **过了自问**   | 不看脚本，说出请求体里必须有哪三个字段？（`model` / `messages` / 别的都不用）                                          |

**卡住怎么办**

| 症状                    | 原因                                          |
| --------------------- | ------------------------------------------- |
| `401`                 | Key 错，或者粘贴时末尾带了看不见的空格                       |
| `404`                 | URL 少了 `/chat/completions`，或模型名拼错           |
| `405`                 | 你填的是 OSS 地址（带 `oss-`），那是存文件的                |
| `ProxyError`          | 本机代理软件没开 → 在 `mykey.py` 里写 `PROXY = "none"` |
| `ModuleNotFoundError` | 用错 python 了，看第 0 节                          |

## 2. 模型没有记忆 —— `02_multi_turn.py`

```bash
& $PY drill.py 2
# 想自己聊几句（这一关最好手动跑）：
& $PY 02_multi_turn.py
```

|           |                                                                           |
| --------- | ------------------------------------------------------------------------- |
| **在证明什么** | 模型是无状态的，"记得"全靠你把 `messages` 一起发过去                                         |
| **该看到**   | 实验 A：第二问它不记得第一问 → 实验 B：记得了 → 实验 C：闯关器替你说了"我叫陈嘉岩"，它&#x56DE;**"你刚才说你叫陈嘉岩"** |
| **重点看数字** | 实验 C 里 `prompt` 一轮比一轮大：37 → 75 → …。**历史是重复计费的**，这就是为什么长对话会变贵              |
| **过了自问**  | 如果一次对话有 40 轮，第 40 轮发过去的 token 是第 1 轮的几倍？                                  |

> 手动跑的时候输入 `exit` 退出，输入 `/show` 能看到真实发出去的 `messages` 长什么样 —— 那个才是模型眼里的全部世界。

## 3. 让模型回代码能读的东西 —— `03_structured_output.py`

```bash
& $PY drill.py 3
```

|            |                                                                             |
| ---------- | --------------------------------------------------------------------------- |
| **在证明什么**  | 提示词里写"请输出 JSON"是**请求**；`response_format` 才是**保证**                           |
| **该看到**    | 实验 A 打印 **`JSONDecodeError`** → 实验 B/C 换成 `response_format` 就稳了 → `第 3 步完成` |
| **正常但像报错** | **实验 A 报错是必须的。** 它是这一关存在的理由。如果实验 A 没报错，说明模型碰巧听话了，重跑一次                       |
| **过了自问**   | 为什么不能只靠提示词？（提示词是概率，解析器是确定性）                                                 |

## 4. 模型只出主意，执行永远是代码 —— `04_tool_calling.py`

```bash
& $PY drill.py 4
```

|            |                                                                                                                              |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **在证明什么**  | 模型返回的不是答案，&#x662F;**"我要调这个函数，参数是这些"**；执行在你这儿                                                                                 |
| **该看到**    | 实验 B 里 `finish_reason` 是 `tool_calls`、`content` 是**空字符串**、`arguments` 是**字符串**（要自己 `json.loads`）→ 实验 D 抽参失败 → 实验 E 加上模糊匹配后成功 |
| **正常但像报错** | 实验 D 里「布洛芬缓释胶囊」被抽成「布洛芬」，**剂型丢了**。这就是真实世界的模型，它不会自己重试                                                                          |
| **过了自问**   | 工具白名单挡的是什么？（挡不住模型"想"调什么，只挡得住它"能"调到什么）                                                                                        |

**三个必记的坑**：`content` 空 / `arguments` 是字符串 / `tool_call_id` 必须原样回传，否则 400。

## 5. 循环 + 刹车 —— `05_agent_loop.py`

```bash
& $PY drill.py 5
```

|            |                                                                                               |
| ---------- | --------------------------------------------------------------------------------------------- |
| **在证明什么**  | 所谓 Agent 就是一个 while 循环 + 四层刹车；停止条件是 `finish_reason`，**不是**轮数                                  |
| **该看到**    | 实验 A 分步查完给出答案 → 实验 B 卡 `max_rounds=1` 时它**明确说"没查完"而不是假装答完** → 实验 C 死循环被刹车拉住 → 实验 D 一张 trace 表 |
| **正常但像报错** | 实验 C 从头到尾在"失败"，那是**本地模拟的假模型**，一分钱不花，专门用来逼出刹车分支                                                |
| **过了自问**   | `status` 有哪几个值？为什么"被叫停"不能记成 `ok`？                                                             |

> 这一关最值钱的是实验 B：**把"被叫停"和"答完了"分清楚**。分不清，前端就会把半截答案当成品展示。

## 6. 接自己的真库 —— `06_his_agent.py`

```bash
& $PY drill.py 6
```

|            |                                                 |
| ---------- | ----------------------------------------------- |
| **在证明什么**  | 只读账号 + SQL 写死 + 参数化，三层叠起来才敢接真数据                 |
| **该看到**    | 五个实验都能查到数；实验 D 里写操作返回 **`1142 command denied`** |
| **正常但像报错** | **`1142` 是这一关的奖章。** 它证明权限卡在了数据库层，不是靠代码自律        |
| **过了自问**   | 模型想删库，为什么删不掉？它会就此罢休吗？                           |

> 实验 D 还有第二个发现：它**执行不了**，但会**把 DELETE 语句教给用户**，甚至编出一个不存在的字段 `is_test`。  
> 所以结论是：**安全边界挡住的是"执行"，挡不住"建议"。** 这句面试可以直接讲。

## 7. 文档塞不进 prompt —— `07_rag_basics.py`

```bash
& $PY drill.py 7      # 一两分钟，中间有静默是正常的
```

|            |                                                                              |
| ---------- | ---------------------------------------------------------------------------- |
| **在证明什么**  | 4 万字文档 → 63 块 → 只喂相关的几块；而且**检索好坏必须量化**                                       |
| **该看到**    | 实验 B 的 `prompt_tokens` 是**两万出头**（全塞的代价）→ 后面 RAG 只要一两千 → 实验 F 的命中率表 → `六句话收尾` |
| **正常但像报错** | 实验 F 的数字会随数据小幅浮动，**别盯着绝对值**，看的是"向量 vs 关键词"的相对关系                              |
| **过了自问**   | 关键词检索最差会掉到第几名？向量呢？（这才是选型的依据）                                                 |

> 这一关埋了整套东西里最深的一课：**金标准怎么标，决定你得什么结论。**  
> 第一版按"标题在哪节"标 → 两边都 2/6 → 得出"换算法没用"；  
> 改按"哪个块含答案关键词"标 → 关键词 4/6、向量 5/6 → 结论反过来了。  
> 你面试被问"你怎么知道检索效果好"，答的就是这个。

## 8. 两个工具合成一个助手 —— `08_rag_agent.py`

```bash
& $PY drill.py 8      # 最慢的一关，一两分钟
```

|            |                                                                                                       |
| ---------- | ----------------------------------------------------------------------------------------------------- |
| **在证明什么**  | 查库工具 + 查文档工具同时给它，**它自己判断该用哪个、按什么顺序**                                                                  |
| **该看到**    | 实验 C 一句话里既有数据又有设计 → 它**第 1 轮同时调两个工具**；实验 D 的噪音题相似度 `0.497`，**过了 0.45 的阈值**，最后是模型自己判断"文档里没写" → `七句话收尾` |
| **正常但像报错** | 中间会静默十几秒，是在跑 Agent 循环，不是卡死                                                                            |
| **过了自问**   | 阈值设 0.45 为什么没拦住 0.497？那这层防线到底有没有用？                                                                    |

> 这一关我**没有**假装防住了。实测正经问题 0.57~~0.74、噪音题 0.47~~0.50，刀口很窄，阈值没关严。  
> 最后兜住的是模型的判断力 —— 这说明**阈值是概率性防线，不是开关**。敢说这句，比吹"我做了阈值过滤"可信得多。

## 9. 做成能点开的网页 —— `09_web_demo.py`

```bash
# 先看它能不能起来（会自动关掉）
& $PY drill.py 9

# 自己点：
& $PY 09_web_demo.py
# 然后开 http://127.0.0.1:5001
```

|            |                                                                |
| ---------- | -------------------------------------------------------------- |
| **在证明什么**  | 流式输出 + 服务端会话；工具调用和"先推文字"会打架，解法是**先推后撤（retract）**               |
| **该看到**    | `健康检查 GET /api/health → 200 {"blocks":63,...}`；浏览器里边说边出字       |
| **正常但像报错** | `WARNING: This is a development server` —— Flask 自带的提示，本地演示无所谓 |
| **过了自问**   | 浏览器关掉再打开，它还记得上一句吗？谁记着？                                         |

> 这一关的核心矛盾：流式要求"我有字就发"，工具调用要求"等我拿到结果再说"。  
> 两者撞上就只能**反悔** —— 先推出去，发现要调工具就发个 `retract` 让前端把气泡清空。

## 三条纪律

**① 一次只跑一关。** 不要一上来 `all`。  
十关串起来跑，中间哪一关炸了你根本不知道是哪一步的锅 —— 而且第 7 关有 `/show` 之类的交互演示，串跑会跳过。

**② 卡住先看 `drill_logs/`。**  
每次运行都有完整日志，文件名带时间。判分只看"终点线那句话"，所以它说没过、而你觉得跑完了，就去日志末尾找停在哪儿。

**③ 每过一关，合上屏幕说一句。**  
说不出来就再过一遍。这套材料的价值不在"跑通"，在你能不能把**为什么这么设计**讲出来 —— 面试官要的就是后半个。

## 最后：这套东西怎么变成面试回答

跑完十关，你手上有五个**真实翻车**，每个都能撑起一段回答：

| 翻车                | 一句话讲法                                                                     |
| ----------------- | ------------------------------------------------------------------------- |
| 提示词要 JSON 结果炸了    | "我原以为写清楚格式就够了，实测发现 `json.loads` 直接抛异常 —— 提示词是请求不是保证，得用 `response_format`" |
| 模型把药名抽丢了剂型        | "布洛芬缓释胶囊被抽成布洛芬，而且它不会自己重试 —— 所以参数校验和模糊匹配必须放在工具侧"                           |
| 金标准标窄，结论反转        | "我先按章节标，两边都 2/6，差点得出'换算法没用'；改按答案所在块标，变成 4/6 和 5/6，结论完全反过来"                |
| 阈值 0.45 没拦住 0.497 | "噪音题相似度 0.497 直接过线，最后是模型自己判断内容不对才拒答 —— 阈值是概率性防线，不是开关"                     |
| 只读账号挡住了执行没挡住建议    | "写操作报 1142 被拒了，但它把 DELETE 语句教给了用户，还编了个不存在的字段"                             |

五个故事，每一个都比"我用 Flask 做了个聊天机器人"有信息量。  
**它们共同证明一件事：你不是照着教程抄完就交，你真的撞过墙、并且知道墙在哪儿。**
